# Fleet Server

## Purpose

This document explains how the Fleet Server was installed and configured in the Home SOC Lab. Fleet Server centrally manages Elastic Agents and enables secure communication between endpoints and Elasticsearch.

---

# Prerequisites

Before installing Fleet Server, ensure that:

- Elasticsearch is running.
- Kibana is running.
- Fleet has been enabled in Kibana.
- The server has internet connectivity.
- SSH access is working.

# Install Elastic Agent

Download the Elastic Agent package.

```bash
wget https://artifacts.elastic.co/downloads/beats/elastic-agent/elastic-agent-9.4.2-linux-x86_64.tar.gz
```

Extract the archive.

```bash
tar -xzf elastic-agent-9.4.2-linux-x86_64.tar.gz
```

Navigate to the directory.

```bash
cd elastic-agent-9.4.2-linux-x86_64
```

---

# Install Fleet Server

Run the installation command generated by Kibana Fleet.

Example:

```bash
sudo ./elastic-agent install \
--fleet-server-es=http://192.168.50.3:9200 \
--fleet-server-service-token=<SERVICE_TOKEN> \
--fleet-server-policy=<POLICY_ID>
```

> Replace the service token and policy ID with the values generated by Kibana.

---

# Verification

Verify that the Elastic Agent service is running.

```bash
sudo systemctl status elastic-agent
```

Check agent health from Kibana.

```
Management → Fleet → Agents
```

The Fleet Server should appear as **Healthy**.

---

# Troubleshooting

### Elastic Agent failed

```bash
sudo journalctl -u elastic-agent
```

---

### Fleet Server Offline

- Verify Elasticsearch is reachable.
- Verify Kibana is reachable.
- Check the service token.
- Verify network connectivity.
